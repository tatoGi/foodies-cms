# PROJECT_MASTER_GUIDE

ეს არის პროექტის არქიტექტურული და კონტენტის მართვის მთავარი დოკუმენტი. იგი აერთიანებს Backend (Laravel) და Frontend (Next.js) ურთიერთქმედების პრინციპებს.

## 1. კონტენტის იერარქია (Content Hierarchy)

პროექტის სტრუქტურა ეყრდნობა სამ მთავარ ბურჯს:

*   **Pages (გვერდები)**: საიტის ძირითადი სტრუქტურა (Home, Services, Projects, Contact).
*   **Posts (პოსტები)**: დინამიური ერთეულები, რომლებიც წარმოადგენენ "ლისტინგის" შიდა შიგთავსს. მაგალითად:
    *   **Services** (Page) -> **Service Detail** (Post)
    *   **Projects** (Page) -> **Project Detail** (Post)
*   **Blocks (ბლოკები)**: მრავალჯერადი კონტენტის სექციები, რომლებიც შეიძლება ჩაიკეროს ნებისმიერ გვერდზე ან პოსტზე.

## 2. დინამიური Slug და SEO Lifecycle (კრიტიკული)

პროექტში **Slug** და **SEO** არის სრულად დინამიური ყველა ტიპის ერთეულისთვის (Page, Post, Product):

*   **Slug Management**: ყოველი თარგმანი (`translation`) ფლობს თავის სლაგს. სლაგის ცვლილებისას სისტემა ავტომატურად ინახავს ძველ სლაგს `slug_aliases` ცხრილში და უზრუნველყოფს `301 Redirect`-ს ახალ ვერსიაზე SEO-ს შენარჩუნებისთვის.
*   **Dynamic SEO**: ყველა გვერდს, პოსტს და პროდუქტს გააჩნია დინამიური SEO ველები (Meta Title, Meta Description, Keywords, Canonical).
*   **SEO Fallback**: სისტემა SEO ველებს ეძებს შემდეგი პრიორიტეტით: მოთხოვნილი ენა -> ნაგულისხმევი ენა -> პირველი ხელმისაწვდომი თარგმანი.

## 3. რელაციები და Cross-Linking

*   **პროდუქტები და პროექტები**: პროდუქტის გვერდზე დინამიურად აისახება მასთან დაკავშირებული პროექტები.
*   **უნივერსალური ვიზუალი**: ნებისმიერი პოსტი ან პროდუქტი, სადაც არ უნდა გამოჩნდეს იგი (Home, Category, Detail), ინარჩუნებს `frontend/newhome`-ში განსაზღვრულ ერთიან ვიზუალურ სტილს.
*   **API Connection**: ყველა რელაცია (Related Posts, Linked Projects) ხელმისაწვდომია API-ს მეშვეობით `include` პარამეტრების გამოყენებით.

## 4. API არქიტექტურა (Laravel -> Next.js Integration)

Next.js (frontend/newhome) გადაბმულია Laravel API-სთან შემდეგი სქემით:

*   **Bootstrap Endoint (`/api/web/bootstrap`)**: აბრუნებს საიტის გლობალურ მონაცემებს (Navigation Menu, Header/Footer Logos, Language Tree).
*   **Page Detail Endpoint (`/api/web/pages/{slug}`)**: აბრუნებს კონკრეტული გვერდის სრულ payload-ს: ბლოკებს, SEO-ს და რელაციებს.
*   **Resource Normalization**: `BlockNormalizationService` უზრუნველყოფს, რომ ბლოკების მონაცემები და მედია ფაილები Next.js-ს მიეწოდოს სწორ და ოპტიმიზირებულ ფორმატში.
